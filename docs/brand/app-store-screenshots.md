# Stou — скриншоты для Mac App Store

**Рабочая редакция v1 · 11 октября 2026**

Тон, тексты, шрифты и палитра — в [brand-voice.md](brand-voice.md); здесь только то, что относится к скриншотам.

## 1. Сюжет Mac App Store: рекомендуемые 6 скриншотов

**Правило:** название и рекламная формулировка должны совпадать с тем, что делает реальный релиз. Сюжет ниже — стратегия **целевого Stou**; в таблице указаны функции, которые ещё нужно подтвердить.

| № | Текст на обложке | Что показано | Допуск к публикации |
|---|---|---|---|
| **01** | **Drop files. Stou takes it from there.** | Большой нативный экран Stou с drag-and-drop. Несколько реалистичных изображений/документов рядом, часть внутри зоны приёма. Ни одного выдуманного системного элемента. | **Есть в Stou 0.19:** Home принимает файлы перетаскиванием и через выбор файлов. |
| **02** | **Tell Stou what’s next.** | После добавления файлов — ясный выбор назначения: Share / Web / Mail / Print / Archive; одна карточка выделена. | **Есть в Stou 0.19:** шесть routines — Send in a chat, Attach to an email, Put on a website, Post on social media, Print, Keep for later. Подписи на кадре брать из приложения, а не Share / Web / Mail / Print / Archive. |
| **03** | **Ready for what’s next.** | Крупное состояние готового результата. Видно, что файлы подготовлены по разным правилам для выбранного назначения; без технической простыни. | **Частично:** routine уже планирует каждый файл (на сайт фото в WebP, скриншоты остаются PNG), полный Processing Planner — в работе. Показывать только то, что делает релиз. |
| **04** | **Right where you need them.** | Подлинный экран Copy / Share / Save to… или его реальное выполнение. Без имитации отправки через третьи сервисы. | **Есть в Stou 0.19:** Where to? — рядом с оригиналами, избранная папка, Choose Folder…, Copy и Share… через системное меню. Внешних сервисов нет. |
| **05** | **One file. Or hundreds.** | Реальная batch-очередь, несколько файлов с осмысленными статусами, прогресс, небольшой summary. | **Есть в Stou 0.19:** пакетная обработка с проверкой каждого файла. |
| **06** | **Your originals stay yours.** | Настройка сохранения оригиналов + экран проверенного результата. Не прятать опцию «keep original» в ложную автоматику. | **Есть в Stou 0.19:** оригиналы по умолчанию остаются; *Move originals to the Trash* включается в Settings и срабатывает только после проверки нового файла; RAW-оригиналы остаются всегда. |

**Опциональные ещё две обложки:**
- **Made for your Mac.** — показать нативную работу Stou, а не нарисованный макет MacBook. Подходит, если локальная обработка и интеграции подтверждены.
- **Less cleanup. More done.** — показать безопасное управление временными файлами. **Частично есть:** готовые файлы ждут в папке Results до доставки, всё старше суток удаляется при запуске; полный Lifecycle Manager — в работе.

**Редакторская дисциплина:** первые три кадра демонстрируют суть и интерес, следующие — передачу результата и доверие. Можно сократить серию до пяти, но не растягивать её до десяти ради количества.

## 2. Композиция одного скриншота

- **Формат:** 2560 × 1600 px (16:10) для macOS. Другие разрешённые Apple: 1280×800, 1440×900, 2880×1800.
- **Экспорт:** RGB PNG/JPEG, **без альфа-канала**.
- **Сетка:** условные внешние поля 112–160 px при 2560 px по ширине; локальные элементы выравниваются по общей модульной сетке.
- **Headline:** Inter SemiBold, ориентировочно 94–120 px для композиции 2560 px. Корректировать под строку и тестировать на масштабе App Store.
- **Supporting line:** по необходимости, ориентировочно 36–46 px. На многих обложках — вообще без неё.
- **UI:** доминирует в композиции; допускается масштабирование, вынос крупных панелей и кадрирование, но нельзя подменять реальный интерфейс выдуманным.
- **Контраст:** очень светлый фон, почти чёрный текст, синий в самих объектах/UI. Не вся обложка синяя; синий должен оставаться ценным акцентом.
- **Динамика серии:** ритм чередуется — широкий hero, крупная деталь, split-композиция, тёмный экран (Stou поддерживает тёмное оформление: Settings › тема).

## 3. Контроль перед публикацией

1. Все скриншоты отражают **реальный интерфейс конкретной собранной версии Stou**, а не концепт.
2. Более половины изображений показывают Stou в действии; для нашей серии — все шесть.
3. Функции обещаются только если реально доступны без скрытых условий. Опциональные расширения и внешние зависимости не маскируются под стандартный функционал.
4. Нет ошибок в английском, терминологии и статусах. Название всегда Stou.
5. Все PNG/JPEG имеют правильные размеры и не содержат прозрачности.
6. Проверен вид карточек в масштабе поиска и магазина: первые 3 читаются сразу.
7. Скриншоты обновляются при заметных изменениях UI.

**Ключевые открытые вопросы перед финальным производством:**
- Какая версия Stou пойдёт в Mac App Store? Routines, Where to? и пакетная обработка уже есть; от состояния Planner и Lifecycle зависят формулировки обложки №03 и опциональной «Less cleanup».
- Как Stou попадёт в Mac App Store технически. Магазину нужны платный аккаунт Apple Developer и приложение в песочнице (App Sandbox), которое не скачивает и не запускает внешний код. Сегодня плагины ставят движки через Homebrew, так что для магазина нужен другой путь — см. план «plugins without Homebrew» в issue #1.
- Перед съёмкой проверить каждый пункт таблицы в собранной версии: статусы выше взяты из README, а не из прогона приложения.
